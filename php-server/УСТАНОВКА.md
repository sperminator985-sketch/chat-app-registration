# Перенос чата «Общага» на свой хостинг

Всё, что нужно — обычный хостинг с PHP 7.4+ и базой MySQL.
Времени займёт примерно 15 минут.

---

## Шаг 1. Создайте базу MySQL

В панели хостинга найдите раздел «Базы данных» (или «MySQL») и создайте новую базу.
Запишите четыре значения, они понадобятся дальше:

- адрес сервера базы (обычно `localhost`)
- имя базы
- имя пользователя
- пароль

## Шаг 2. Впишите эти данные в файл config.php

Откройте `config.php` в блокноте и замените значения на свои:

```php
'db_host' => 'localhost',
'db_name' => 'ваша_база',
'db_user' => 'ваш_пользователь',
'db_pass' => 'ваш_пароль',

'base_url' => 'https://ваш-домен.ru/chat',
'install_key' => 'придумайте-пароль',

'allowed_origins' => [
    'https://ваш-домен.ru',
    'https://www.ваш-домен.ru',
],
```

`base_url` — адрес папки, куда вы положите файлы (без слэша в конце).
`install_key` — любой пароль, он нужен один раз для установки.
`allowed_origins` — адреса вашего сайта. Чужим сайтам чат отвечать не будет.

## Шаг 3. Загрузите файлы на хостинг

Через файловый менеджер панели или по FTP загрузите папку целиком
в корень сайта под именем `chat`. Должно получиться так:

```
public_html/
  chat/
    api.php
    config.php
    db.php
    install.php
    .htaccess
    uploads/     ← создастся сама
```

## Шаг 4. Создайте таблицы

Откройте в браузере:

```
https://ваш-домен.ru/chat/install.php?key=ПАРОЛЬ_ИЗ_CONFIG
```

Должно появиться «Готово! Таблицы созданы.»
Заодно создадутся таблицы для шифрования личных сообщений и журнала безопасности.
Если пишет про папку uploads — создайте её вручную и поставьте права 755.

**После этого удалите файл `install.php` с хостинга.**

### Если чат уже работает — install.php запускать не нужно

При обновлении на версию с шифрованием достаточно залить новый `api.php` — все нужные
таблицы он создаст сам при первом обращении.

Исключение: если у пользователя базы нет прав на создание таблиц (бывает на дешёвых
тарифах), автосоздание молча не сработает и Сейф не включится. Тогда выполните SQL вручную:

1. Откройте phpMyAdmin, выберите базу чата
2. Вкладка **SQL**
3. Откройте файл `crypto-tables.sql` из этого архива, скопируйте всё содержимое, вставьте
4. Нажмите **Вперёд**

Скрипт безопасен: существующие данные не трогает, запускать можно повторно.
Создаёт таблицы `user_keys`, `vault_key`, `login_attempts`, `security_log`
и добавляет колонки `direct_messages.cipher`, `users.last_ip`, `users.last_city`.

## Шаг 5. Переключите сайт на свой сервер

В проекте сайта откройте файл `src/lib/api.ts` и в самом верху замените адрес:

```js
const API_URL = 'https://ваш-домен.ru/chat/api.php';
```

Опубликуйте сайт заново. Готово — чат работает на вашем хостинге без лимитов.

---

## Проверка, что всё работает

Откройте в браузере:

```
https://ваш-домен.ru/chat/api.php?action=feed&room=kurilka
```

Должен появиться текст вида `{"messages":[],"online":[],...}` — значит, сервер отвечает.

## Если что-то пошло не так

**Белая страница или ошибка 500** — скорее всего, неверные данные базы в `config.php`.
Проверьте имя базы, пользователя и пароль.

**«Ошибка на сервере чата»** — посмотрите файл логов ошибок в панели хостинга,
там будет строка, начинающаяся с `chat api:`.

**Аватарки не загружаются** — папке `uploads` нужны права на запись (755 или 777).

**Чат не видит сервер, в браузере ошибка CORS** — убедитесь, что сайт и чат
открываются по `https://`, а не по `http://`.

## Что перенеслось, а что изменилось

Работает так же: регистрация, вход, сообщения по девяти этажам, личные сообщения,
профиль с аватаркой, счётчики онлайна, звонки между жильцами,
а также панель владельца по адресу /admin.

Владельцем становится тот, кто зарегистрирует ник «Админ» — права выдаются
автоматически при регистрации. Чтобы назначить владельцем другого,
выполните в панели хостинга (phpMyAdmin) запрос:
UPDATE users SET is_admin = 1 WHERE nick = 'нужный_ник';

Единственное отличие: аватарки теперь хранятся в папке `uploads` на вашем хостинге,
а не в облаке. Старые пользователи и переписка на новый сервер не переносятся —
чат начнёт с чистого листа. Если нужно перенести и их, скажите, подготовлю выгрузку.

## Шифрование личных сообщений

Личная переписка может храниться в базе в зашифрованном виде. Читать её сможете
только вы — даже при полной утечке базы сообщения останутся нечитаемым набором символов.

### Как включить

1. Зайдите на сайт под своим ником владельца
2. Откройте комендантскую → раздел **Сейф**
3. Придумайте пароль-фразу (от 12 символов) и нажмите «Создать ключ»
4. Файл ключа `obshaga-master-key.json` скачается автоматически — сохраните его
   в надёжном месте и сделайте вторую копию

С этого момента вся новая личная переписка шифруется автоматически.
Жильцам ничего делать не нужно — их ключи создаются сами при входе.

### Как прочитать переписку

Комендантская → **Сейф** → загрузите файл ключа, введите пароль-фразу → «Открыть».
Расшифровка происходит прямо в вашем браузере, ключ на сервер не отправляется.

### Что где хранится

- `user_keys` — ключи жильцов. Закрытая часть зашифрована паролем жильца,
  сервер прочитать её не может
- `vault_key` — только открытая часть вашего главного ключа. Закрытая часть
  на сервере не хранится никогда
- `direct_messages.cipher` — сами зашифрованные сообщения

### Важно

- Потеряете файл ключа и забудете пароль-фразу — переписку не восстановит никто.
  Механизма восстановления не существует, это не забывчивость разработчика,
  а суть шифрования
- Замена ключа делает всю переписку под старым ключом нечитаемой
- Если жилец забудет пароль и восстановит его через почту, свою старую переписку
  он потеряет. У вас она останется
- Общие чаты по этажам не шифруются — иначе не работали бы поиск и модерация

### Что используется

Алгоритмы стандартные, встроены в браузер (Web Crypto API), ничего стороннего
не подключается:

- RSA-OAEP 2048 бит — обмен ключами
- AES-GCM 256 бит — шифрование текста
- PBKDF2, 210 000 итераций, SHA-256 — защита ключа паролем

## Защита от взлома

Уже встроено в `api.php`, настраивать не нужно:

- Пароли хранятся как bcrypt-хеши — восстановить их нельзя даже из базы
- 10 неудачных попыток входа — блокировка на 15 минут
- Антиспам: не больше 8 сообщений за 10 секунд, повторы отклоняются
- Сессии живут 90 дней, потом нужен повторный вход
- Все запросы к базе параметризованы — SQL-инъекции невозможны
- Заголовки: запрет встраивания в чужой iframe, обязательный HTTPS

Журнал подозрительной активности — комендантская → **Журнал**.
Хранится 30 дней, чистится автоматически.
## Если весь сайт в папке chat отдаёт «500 Internal server error»

Признак: ошибка 500 на ВСЁМ, что лежит в папке — не только на `api.php`, но и на
картинках и текстовых файлах. Значит дело не в коде и не в `config.php`, а в `.htaccess`.

Причина: некоторые хостинги (в том числе reg.ru) запрещают в `.htaccess` секцию
`<Directory>` и директиву `php_flag`. Apache при встрече с запрещённой директивой
роняет всю папку.

Решение: замените `.htaccess` на новый из архива. В нём запрещённые директивы убраны,
а защита папки `uploads` перенесена в отдельный файл `uploads/.htaccess`.

Если новый `.htaccess` не помог — удалите его совсем. Чат заработает, но пропадёт
защита от скачивания `config.php`. В этом случае переименуйте `config.php` в
что-нибудь непредсказуемое и поправьте имя в `db.php`.
